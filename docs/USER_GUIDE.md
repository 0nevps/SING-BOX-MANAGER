# 使用指南

当前是开发预发布版，只在独立测试机上使用。真实 systemd 服务、证书申请和客户端连接仍需在 Linux 上验收；保存设置成功不等于节点可以连接。

## 先认识节点、用户和出口

- **节点（手机或电脑连接的入口）**：本工具提供 REALITY、Hysteria2 和 WebSocket 三种节点。
- **用户**：可以单独设置节点使用权限、启用或停用的连接身份。
- **出口（VPS 访问网络时使用的线路）**：同一个用户在不同节点上，可以使用不同出口。
- **直连（DIRECT，不经过代理出口）**：让 VPS 直接访问网络。
- **连接密钥（UUID 或密码）**：客户端连接节点时使用的信息，不要公开。

输入菜单编号即可操作。需要填写 ID 时，从“查看当前设置”复制对应的 ID，不需要自己编写。

## 菜单能做什么

| 编号 | 菜单名称 | 用途 |
| --- | --- | --- |
| 1 | 查看当前设置 | 查看用户、节点、出口及使用关系，复制操作需要的 ID。 |
| 2 | 添加用户 | 创建用户，之后还需要允许该用户使用节点。 |
| 3 | 添加节点 | 填写名称和协议，先建立节点记录；地址和端口在菜单 13 设置。 |
| 4 | 允许用户使用节点 | 为指定用户开通指定节点，并生成该节点的连接密钥。 |
| 5 | 添加 SOCKS5 出口 | 保存 SOCKS5 服务器地址、端口、用户名和密码。 |
| 6 | 切换用户出口 | 为一个用户在一个节点上选择出口，或选择直连。 |
| 7 | 启用或停用用户 | 输入 `enable` 启用，输入 `disable` 停用。 |
| 8 | 取消用户的节点权限 | 取消该用户对指定节点的使用权限，并清除该节点下保存的出口选择。 |
| 9 | 删除用户 | 删除用户及其全部节点权限、出口选择。 |
| 10 | 删除出口 | 删除不再被任何用户保存使用的出口。 |
| 11 | 重置连接密钥 | 更换指定用户在指定节点上的 UUID 或密码。 |
| 12 | 移除已保存的出口 | 从一个用户的一个节点中移除已保存的出口，不会删除出口本身。 |
| 13 | 设置节点地址和端口 | 填写或修改节点地址、端口、证书域名及协议参数。 |
| 14 | 检查配置并启动服务 | 检查配置后应用到系统服务；只在 Linux 系统模式下使用。 |
| 15 | 导出客户端配置 | 为已启用用户生成客户端配置和分享链接。 |
| 16 | 测试出口连接 | 检查 SOCKS5 握手和用户名、密码，不检查实际转发或 UDP。 |
| 17 | 修改出口 | 重新填写已有出口的名称、地址、端口和账号等信息。 |
| 18 | 查看服务状态 | 查看系统服务是否运行。 |
| 19 | 查看服务日志 | 查看系统服务的日志。 |
| 20 | 检查证书 | 查看域名解析结果和本地缓存证书的有效期。 |
| 21 | 创建备份 | 保存当前管理数据和服务配置的备份。 |
| 22 | 查看备份列表 | 列出备份文件名，供恢复时复制。 |
| 23 | 从备份恢复 | 输入备份文件名，确认后恢复其中的管理数据并重新生成、应用配置。 |
| 24 | 设置备份保留数量 | 只保留最近指定数量的备份，至少 1 份，多出的备份会被删除。 |
| 25 | 为用户开通全部节点 | **新建一个用户**并允许其使用所有已有节点，不是给已有用户追加权限。 |
| 26 | 首次设置向导 | 没有用户和节点时，创建三种节点及第一个用户，不覆盖已有数据。 |
| 27 | 升级 sing-box | 在系统模式下升级到指定的 1.14.x 稳定版本。 |
| 0 | 退出 | 关闭管理菜单。 |

菜单 14、18–24、27 需要安装后的 Linux root 系统模式。本地模式只保存管理数据，不会操作系统服务。

## 用户、节点和出口 ID 去哪里找

先打开“查看当前设置”（菜单 1），按名称找到要操作的对象，再复制它的 `id`。**用户 ID、节点 ID、出口 ID 不是名称，也不是客户端连接使用的 UUID 或密码。** 输入 ID 时不要带上 JSON 的引号或逗号。

当前设置以 JSON 格式显示。只需先认清下面几个字段，不需要手写或修改 JSON：

| 字段 | 含义 |
| --- | --- |
| `users` | 用户列表；每个用户的 `id` 是用户 ID，`name` 是用户名。 |
| `inbounds` | 节点列表；每个节点的 `id` 是节点 ID，旧提示中的“入站 ID”也是它。 |
| `egress` | 出口列表；每个出口的 `id` 是出口 ID。 |
| `protocol` | 协议名称：`reality`、`hysteria2`、`cloudflare_ws` 或出口的 `socks5`。 |
| `enabled` | 用户是否启用：`true` 是启用，`false` 是停用。 |
| `grants` | 该用户获准使用的节点 ID 列表，不显示连接密钥。 |
| `bindings` | 用户在各节点上的出口设置，包含 `user_id`、`inbound_id`、`saved` 和 `active`。 |
| `saved` | 这个用户在这个节点上保存过的出口 ID。 |
| `active` | 当前使用的出口 ID；`null` 表示直连（DIRECT，不经过代理出口）。没有对应的出口设置时也默认直连。 |
| `settings` | 节点的地址、端口等参数，或出口的服务器和账号等参数。 |

列表会隐藏部分敏感字段，但不要因此把整份数据当作可以公开的内容。客户端连接密钥需要通过“导出客户端配置”获取，不是从 `id` 字段复制。

## 第一次设置与手工添加

首次设置向导会创建三种节点和第一个用户，并允许该用户使用这三个节点。第一个用户名直接回车默认为 `default`，也可以自己填写。已有用户或节点时，向导不会覆盖数据。

手工添加时，按下面顺序操作：

1. 用“添加节点”填写名称和协议，再用“设置节点地址和端口”补全连接参数。
2. 用“添加用户”创建用户。
3. 从“查看当前设置”复制用户 ID 和节点 ID，再用“允许用户使用节点”开通权限。
4. 如果要使用代理出口，先“添加 SOCKS5 出口”，再“切换用户出口”。不设置代理出口时默认直连。
5. 系统模式下首次使用需要“检查配置并启动服务”，之后才能继续检查客户端连接。

每个用户在每个节点上的权限和连接密钥是分开的。停用用户会保留节点权限和出口设置；取消某个节点权限只清除该节点下的权限和出口设置；删除用户会清除该用户的全部权限和出口设置。

重置连接密钥后，该用户在对应节点上的旧客户端配置会失效，需要重新导出并更新客户端。

## 节点地址、端口和 WebSocket 路径

每种协议只询问一次“在 VPS 上使用的端口”：

- REALITY 默认 TCP 443，手机或电脑直接连接这个端口。
- Hysteria2 默认 UDP 443，手机或电脑直接连接这个端口。
- WebSocket 先选择直接连接 VPS，还是经过 Cloudflare 代理，再填写 VPS 端口，默认 TCP 8443。直接连接 VPS 时，客户端使用相同端口；经过 Cloudflare 时，客户端连接 HTTPS 443，需要你自行在 Cloudflare 设置回源到 VPS 所填端口的规则。

这里的“直接连接 VPS”是手机到 VPS 的连接方式，与 VPS 访问网络时使用的直连出口是两回事。程序只生成节点配置，不会自动设置 Cloudflare。

修改旧配置时，如果已有不同的客户端端口和 VPS 端口，程序会提示保留原设置还是重新设置，避免覆盖已有端口转发安排。

WebSocket 路径首次留空会随机生成并显示；修改已有节点时留空会保留原路径。路径需要以 `/` 开头，不能包含空格、`?` 或 `#`。更改路径或端口后，请重新导出客户端配置，并同步更新 Cloudflare 等转发服务的规则。

## REALITY 的握手目标和 SNI

握手目标是 REALITY 使用的目标服务器；SNI 是握手时发送的域名，需要与目标证书匹配。

首次设置或修改 REALITY 节点时，先填写握手目标域名，再填写 SNI。SNI 留空会使用同一个域名；也可以自己填写与目标证书匹配的其他域名。程序没有固定的备选域名列表。

保存前，程序会连接目标的握手端口，默认 TCP 443，检查：

- 能否连接并完成 TLS 1.3 握手。
- 证书是否由系统信任的 CA 签发、是否在有效期内，以及是否与 SNI 匹配。

连接、握手或证书检查失败时，不保存修改。检查从运行管理器的机器发出，在本地电脑检查通过不代表 VPS 也能连接目标。基础检查也不能证明目标满足所有 REALITY 条件，仍需用 REALITY 客户端实际测试。

WebSocket TLS 应填写你自己的节点证书域名，不使用 REALITY 的默认规则。

## 添加和切换出口

“添加 SOCKS5 出口”需要填写服务器地址、端口、用户名和密码。是否支持 UDP 需要你根据出口服务的实际情况明确填写；程序不会自动测出 UDP 能力。

“测试出口连接”只检查 SOCKS5 握手和账号密码是否通过，不证明出口能转发到目标网站，也不证明 UDP 可用。不支持 UDP 的代理出口会阻止 UDP 流量，不会自动改用 VPS 直连。

“切换用户出口”需要填写用户 ID、节点 ID 和出口 ID，只改变这个用户在这个节点上的线路。**出口 ID 留空表示选择直连（DIRECT，不经过代理出口）**，不是保留原设置。

切换后，之前的出口仍保存在该用户的这个节点下。需要移除时，使用“移除已保存的出口”；如果它正在使用，先切换到另一个出口或直连，再移除。

“删除出口”会删除出口本身。只要有用户仍保存着这个出口，即使没有正在使用，也不能删除。请先在相关用户和节点下移除它。

## 检查配置、启动服务和导出

“检查配置并启动服务”会调用 sing-box 检查生成的配置，再写入配置、启动或重启服务，并检查服务和监听端口。首次成功后，用户、节点和出口等设置的修改也会自动检查并更新服务。

应用失败时，程序会尝试恢复之前的管理数据、配置和服务状态。如果恢复也失败，会保留 `transaction.json` 恢复记录并阻止继续修改。请先检查服务日志和系统环境，不要删除恢复记录来绕过保护。

“导出客户端配置”需要填写已启用用户的 ID，以及一个**尚不存在的新目录**，会生成：

- `client.json`：客户端配置，包含本机 `127.0.0.1:2080` 的混合代理入口和可切换的节点列表。
- `links.txt`：该用户有权使用的节点分享链接。

导出目录使用 `0700` 权限，文件使用 `0600` 权限。导出内容含有连接密钥，请像密码一样保管，不要提交到代码仓库、公开上传或贴出完整分享链接。导出成功不代表节点已经连接测试通过。

## 备份、恢复和排查问题

在系统模式下，使用“创建备份”“查看备份列表”“从备份恢复”和“设置备份保留数量”管理备份。恢复时从备份列表复制文件名；确认恢复会替换当前管理数据和配置，输入 `yes` 才会继续。恢复前会检查配置，并另存一份当前数据的备份。

设置保留数量时至少保留 1 份，超出数量的旧备份会被删除。备份含有明文密码和连接密钥，不要公开。若有未完成的配置恢复，下次读写数据前会先尝试恢复；失败时先解决服务或环境问题，不要手动删除恢复记录。

“检查证书”只显示 DNS 解析结果和本地缓存证书的有效期，实际申请与续期由 sing-box 完成。这些结果不能证明公网证书验证已经通过。

连接失败时，结合“查看服务状态”“查看服务日志”和“检查证书”排查，并确认域名指向正确地址、HTTP-01 使用的公网 TCP 80 可以到达 VPS 源站、节点端口可达，再用客户端实际测试。V1 不支持 DNS-01，Cloudflare 的解析、代理和回源规则需要自行设置。
