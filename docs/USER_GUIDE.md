# 使用指南

`sbmanager` 和 `python3 main.py` 都要求 Linux + root，统一使用 `/var/lib/sbmanager/` 保存管理数据、`/etc/sbmanager/config.json` 保存服务配置，并管理真实系统服务。普通用户请用 `sudo sbmanager` 启动，已在 root 终端中时可直接运行 `sbmanager`。

保存设置成功不等于节点可以连接。请检查服务状态、证书和网络，并使用客户端实际测试。

## 先认识节点、用户和出口

- **节点（手机或电脑连接的入口）**：本工具提供 REALITY、Hysteria2、WebSocket 和 AnyTLS 四种节点。
- **用户**：可以单独设置节点使用权限、启用或停用的连接身份。
- **出口（VPS 访问网络时使用的线路）**：同一个用户在不同节点上，可以使用不同出口。
- **直连（DIRECT，不经过代理出口）**：让 VPS 直接访问网络。
- **连接密钥（UUID 或密码）**：客户端连接节点时使用的信息，不要公开。

输入菜单编号即可操作。先选择分类，再选择具体功能；选择用户、节点或出口时，按名称找到对象并输入列表编号，不需要复制 ID。各子菜单输入 `0` 返回主菜单，选择对象时输入 `0` 取消当前选择。

菜单采用居中标题、绿色等号分隔线和 `1)` 形式的单列编号，底部统一提示“请输入选项 [0-N]:”；主菜单从第 1 项起为“业务配置”、第 5 项起为“运行与维护”、第 7 项起为“系统设置”，子菜单不设额外分组标题。标签和普通选项使用绿色，主机信息和普通编号使用蓝色，未运行服务和危险操作使用红色，提示和返回编号使用黄色。危险操作仍标记 `[危险]`，需留意的操作仍标记 `[注意]`，不只依赖颜色区分。菜单标题、标签和状态会按终端宽度折行，分隔线最长 56 列；不清屏，方便回看操作结果。交互终端使用颜色，重定向输出、`TERM=dumb` 或设置 `NO_COLOR` 时使用纯文本，例如 `NO_COLOR=1 sbmanager`。

## 菜单能做什么

下文用“主菜单 → 子菜单”表示操作路径。例如“2 用户管理 → 5 开通节点”，就是先输入 `2`，再输入 `5`。

### 4 端口转发

- **1 查看转发**：显示名称、协议、监听地址和目标地址。
- **2 添加转发**：填写名称、监听 IP、监听端口、目标 IP/域名和目标端口。监听默认 `0.0.0.0`（全部 IPv4 地址），协议默认 TCP + UDP，也可仅选 TCP 或 UDP；IPv6 监听可填写 `::`。输入 `0` 取消。
- **3 删除转发**：按编号选择规则，输入 `y` 确认删除。

转发使用 sing-box 原生 `direct` 入站和直连出站，不经过用户代理出口，无需创建用户、代理节点或申请证书。首次保存后，执行“5 服务管理 → 2 检查配置并启动服务”；首次启动成功后，转发的添加和删除自动应用，失败时复用现有回滚流程。删除最后一条转发后允许服务保持运行但不再监听转发端口。

相同协议和端口不能重复用于转发或已有节点，即使监听地址不同也保守判为冲突；TCP 和 UDP 可分别使用同一端口。存在需要 ACME 证书的节点时，TCP 80 保留给证书验证。已有数据没有 `forwards` 字段时按无转发处理，原有节点、用户和出口不变。

**监听公网地址会向可访问该端口的设备开放转发，转发本身不提供身份认证或额外加密。** 请自行限制防火墙和云安全组，分别放行需要的 TCP/UDP。目标通常看到转发服务器 IP，不保留客户端源 IP。避免将目标指回本机监听端口；程序不能识别所有经域名或外部网络形成的转发环路。服务与监听检查通过不代表目标可达，仍需从外部实际测试 TCP 和 UDP。

#### 节点流量仅用 IPv4

选择“7 网络设置 → 1 节点流量仅用 IPv4”，查看“当前状态：已开启 / 已关闭”，选择“开启”或“关闭”，输入 `y` 确认。输入 `0` 或不确认则不修改；选择与当前相同的状态也不修改。

- 默认关闭，已有数据没有此设置时保持原有行为。设置随管理数据保存，后续更新和重启保留；备份恢复时恢复对应备份中的设置，旧备份没有此设置时按关闭处理。
- 开启后，使用 VPS 本机出口（直连）的所有节点仅通过 IPv4 访问网站和其他目标。域名只解析 IPv4，客户端直接提交的 IPv6 目标地址也会被拒绝；仅支持 IPv6 的目标无法访问，不会回退到 IPv6。
- 不修改服务器全局设置，不禁用系统 IPv6，不修改节点监听地址，不影响客户端通过 IPv6 连接节点，也不影响独立端口转发。此设置不是全机 IPv6 出站防火墙，不限制证书申请、系统 DNS 等其他连接。
- 用户绑定 HTTP、SOCKS5 或 SS 代理出口时，该流量及到代理服务器的连接不受此设置控制；切回直连后受此设置限制。
- 首次部署前仅保存设置，仍需执行“5 服务管理 → 2 检查配置并启动服务”。已部署后修改会检查配置并重启服务，连接可能短暂中断；应用失败时复用原有的数据、配置和服务回滚流程。
- 关闭后移除上述 IPv4 限制，不代表强制使用 IPv6，实际连接仍取决于目标地址和 VPS 网络。

实现使用独立的 `direct` 出站及 `domain_resolver.strategy: ipv4_only`，配合节点路由中的 IPv6 目标拒绝规则；代理出口规则优先匹配，端口转发仍使用原直连出站。官方依据：[拨号字段](https://sing-box.sagernet.org/configuration/shared/dial/#domain_resolver)、[迁移说明](https://sing-box.sagernet.org/migration/#migrate-outbound-domain-strategy-option-to-domain-resolver)、[路由规则](https://sing-box.sagernet.org/configuration/route/rule/)、[拒绝动作](https://sing-box.sagernet.org/configuration/route/rule_action/#reject)。配置检查通过不等于客户端连通性已经通过，仍需在双栈 VPS 上通过客户端分别验证 IPv4 和 IPv6 目标。

#### 开启 BBR

选择“7 网络设置 → 2 开启 BBR”，输入 `y` 确认。此操作影响全机 TCP 默认拥塞控制，不只影响 sing-box：

- 检查当前内核可用算法，必要时尝试加载 `tcp_bbr`；不下载或更换内核，不重启系统或 sing-box。
- 设置 `net.core.default_qdisc=fq` 和 `net.ipv4.tcp_congestion_control=bbr`，检查运行值后，将这两个参数保存到 `/etc/sysctl.d/99-sbmanager-bbr.conf`（权限 `0600`）。不修改其他 sysctl 文件，也不运行全局 `sysctl --system`。
- 内核不支持时提示错误，不修改这两个参数；容器可能没有相应权限或依赖宿主机内核。应用或保存失败时尝试恢复原参数和该文件，恢复不完整会明确提示需要手动检查。
- BBR 是 TCP 拥塞控制，不改变 Hysteria2 的 QUIC 拥塞控制，也不保证网速提升。默认队列设置不等于替换已有网卡队列，已有 TCP 连接不保证切换算法。

重启后其他 sysctl 配置仍可能覆盖这些参数，请以主菜单显示的当前运行状态为准。本工具不提供关闭 BBR 操作；如需撤销，请自行恢复原 TCP 拥塞控制和默认队列，并移除或调整上述配置文件。管理数据备份不包含该系统级文件，卸载也不会撤销 BBR 或删除该文件。

### 8 更新与卸载

| 编号 | 菜单名称 | 用途 |
| --- | --- | --- |
| 1 | 更新管理程序 | 从安装来源仓库的 main 下载最新安装器，保留数据和配置，更新后重新加载菜单。 |
| 2 | 升级 sing-box | 升级到指定的 1.14.x 版本。 |
| 3 | 卸载全部 | 停止并移除本工具的服务，永久删除安装文件、数据、配置、证书缓存、备份及 sbmanager 指令。 |
| 0 | 返回 | 返回主菜单。 |

更新管理程序时，安装器会在终端要求输入 `y` 确认；服务正在运行时可能短暂中断，失败时尝试回滚。卸载前会列出具体路径，只有输入 `y` 才执行，其他输入取消。卸载无法撤销，成功后退出程序；手动导出到其他目录的文件、共享系统日志和系统依赖不会删除。

服务操作和备份恢复直接影响真实系统服务及其数据。确认提示统一使用 `[y/N]`：输入 `y` 或 `Y` 确认，输入 `n`、`N` 或直接回车取消，其他输入也不会执行。删除、取消权限、重置密钥、恢复等危险操作仍需按提示确认；确认前请核对对象和影响，不要把确认当作普通的下一步。

## 按名称和编号选择对象

默认显示友好列表，不再要求从 JSON 中复制用户、节点或出口 ID。可以先在相应分类的“查看节点”“查看用户”“查看出口”中了解当前设置，再进入操作并按名称选择编号。编号以当前显示的列表为准；选择对象时输入 `0` 取消。

切换出口时，直连（DIRECT，不经过代理出口）是列表中的明确编号选项。需要直连时输入它对应的编号；不要留空回车，也不要输入或复制出口 ID。`0` 表示取消，不表示直连。

## 查看原始设置 JSON

只有“5 服务管理 → 5 查看原始设置 JSON”显示原始设置 JSON，日常操作不需要使用。**用户 ID、节点 ID、出口 ID 不是名称，也不是客户端连接使用的 UUID 或密码。** 排查时可参考以下字段，不需要手写或修改 JSON：

| 字段 | 含义 |
| --- | --- |
| `users` | 用户列表；每个用户的 `id` 是用户 ID，`name` 是用户名。 |
| `inbounds` | 节点列表；每个节点的 `id` 是节点 ID，旧提示中的“入站 ID”也是它。 |
| `egress` | 出口列表；每个出口的 `id` 是出口 ID。 |
| `protocol` | 协议名称：`reality`、`hysteria2`、`cloudflare_ws`、`anytls` 或出口的 `http`、`socks5`、`ss`。 |
| `enabled` | 用户是否启用：`true` 是启用，`false` 是停用。 |
| `grants` | 该用户获准使用的节点 ID 列表，不显示连接密钥。 |
| `bindings` | 用户在各节点上的出口设置，包含 `user_id`、`inbound_id`、`saved` 和 `active`。 |
| `saved` | 这个用户在这个节点上保存过的出口 ID。 |
| `active` | 当前使用的出口 ID；`null` 表示直连（DIRECT，不经过代理出口）。没有对应的出口设置时也默认直连。 |
| `settings` | 节点的地址、端口等参数，或出口的服务器和账号等参数。 |

列表会隐藏部分敏感字段，但不要因此把整份数据当作可以公开的内容。客户端连接信息可通过“节点管理 > 查看节点”中的用户分享链接获取，不是从 `id` 字段复制。

## 第一次设置

每次运行 `sbmanager` 都先显示主菜单，首次使用也不会自动进入设置。安装器完成后，有交互终端时也会打开主菜单。

按下面顺序操作：

1. 用“1 节点管理 → 2 添加节点”一次填写协议、名称和连接参数。名称默认使用协议全名，重名时自动追加编号；输入 `0` 取消，不保存半成品节点。后续通过“3 修改节点”调整参数，名称不可修改。
2. 用“2 用户管理 → 2 添加用户”创建用户。
3. 用“2 用户管理 → 5 开通节点”，按名称和编号选择用户、节点并开通权限。也可以用“2 用户管理 → 3 添加用户并开通全部节点”一次创建新用户并开通全部已有节点。
4. 如果要使用代理出口，先用“3 出口管理 → 2 添加出口”，再用“3 出口管理 → 5 切换用户出口”。不设置代理出口时默认直连。
5. 首次使用需要主动选择“5 服务管理 → 2 检查配置并启动服务”，之后才能继续检查客户端连接。

每个用户在每个节点上的权限和连接密钥是分开的。停用用户会保留节点权限和出口设置；取消某个节点权限只清除该节点下的权限和出口设置；删除用户会清除该用户的全部权限和出口设置。

重置连接密钥后，该用户在对应节点上的旧客户端配置会失效，需要到“节点管理 > 查看节点”获取新分享链接并更新客户端。

## 节点地址、端口和 WebSocket 路径

每种协议只询问一次“在 VPS 上使用的端口”：

- REALITY 默认 TCP 443，手机或电脑直接连接这个端口。
- Hysteria2 默认 UDP 443，手机或电脑直接连接这个端口。
- AnyTLS 默认 TCP 443，手机或电脑直接连接 VPS；与 REALITY 或其他 TCP 节点共存时需要不同的 TCP 端口。
- WebSocket 先选择直接连接 VPS，还是经过 Cloudflare 代理，再填写 VPS 端口，默认 TCP 8443。直接连接 VPS 时，客户端使用相同端口；经过 Cloudflare 时，客户端连接 HTTPS 443，需要你自行在 Cloudflare 设置回源到 VPS 所填端口的规则。

这里的“直接连接 VPS”是手机到 VPS 的连接方式，与 VPS 访问网络时使用的直连出口是两回事。程序只生成节点配置，不会自动设置 Cloudflare。

修改旧配置时，如果已有不同的客户端端口和 VPS 端口，程序会提示保留原设置还是重新设置，避免覆盖已有端口转发安排。

WebSocket 路径首次留空会随机生成并显示；修改已有节点时留空会保留原路径。路径需要以 `/` 开头，不能包含空格、`?` 或 `#`。更改路径或端口后，请到“节点管理 > 查看节点”获取新分享链接并更新客户端，并同步更新 Cloudflare 等转发服务的规则。

## AnyTLS 节点

在“1 节点管理 → 2 添加节点”的协议列表选择“4 AnyTLS”，填写 VPS 端口、公网地址和自己的证书域名。证书由 sing-box 通过现有 ACME HTTP-01 流程申请和续期，需要域名指向 VPS，公网 TCP 80 可达，并放行节点的 TCP 端口。

AnyTLS 使用原生 TLS，不是 WebSocket，不能经过 Cloudflare 普通橙云 HTTP 代理；使用 Cloudflare DNS 时请设为仅 DNS（灰云），直接连接 VPS。不需要填写 WebSocket 路径或 REALITY 握手目标。

每个用户在每个 AnyTLS 节点上使用独立随机密码，沿用用户授权、停用、重置密钥和出口绑定功能。通过“节点管理 → 查看节点”获取 `anytls://` 分享链接，导入支持 AnyTLS 的客户端；重置密码后需重新获取链接。TLS 证书校验默认开启，不生成跳过验证参数。服务端填充策略和客户端会话参数使用 sing-box 默认值。

AnyTLS 使用 TCP 监听；客户端如需转发 UDP，须支持协议的 UDP over TCP。用户绑定不支持 UDP 的代理出口时，仍会阻止 UDP，不会回退到 VPS 直连。本次仅增加 AnyTLS 入站节点，不支持在“出口管理”中添加 AnyTLS 代理出口。

协议字段与分享链接格式参考：[sing-box AnyTLS 入站](https://sing-box.sagernet.org/configuration/inbound/anytls/)、[sing-box AnyTLS 客户端出站](https://sing-box.sagernet.org/configuration/outbound/anytls/)、[AnyTLS URI 规范](https://github.com/anytls/anytls-go/blob/main/docs/uri_scheme.md)。

## REALITY 的握手目标和 SNI

握手目标是 REALITY 使用的目标服务器；SNI 是握手时发送的域名，需要与目标证书匹配。

添加或修改 REALITY 节点时，只填写一次“REALITY 目标网站域名”，程序将同一个域名用于握手目标和 SNI，不再分别询问。请填写目标网站的域名，不要填写 IP、URL、端口或路径。程序没有固定的备选域名列表。

已有配置不会因更新程序而自动改写。如果旧配置的握手目标与 SNI 不同，修改节点时默认显示原 SNI；保存后两项统一为本次填写的域名，取消或校验失败则保留原配置。

保存前，程序会连接目标的握手端口，默认 TCP 443，检查：

- 能否连接并完成 TLS 1.3 握手。
- 证书是否由系统信任的 CA 签发、是否在有效期内，以及是否与 SNI 匹配。

连接、握手或证书检查失败时，不保存修改。检查从运行管理器的机器发出，在本地电脑检查通过不代表 VPS 也能连接目标。基础检查也不能证明目标满足所有 REALITY 条件，仍需用 REALITY 客户端实际测试。

WebSocket TLS 应填写你自己的节点证书域名，不使用 REALITY 的默认规则。

## 添加和切换出口

“3 出口管理 → 2 添加出口”先输入分享链接（完整内容可见，不隐藏、脱敏或截断，输入 `0` 取消；链接可能含账号和密码，请勿公开终端截图或录屏），自动解析协议、地址、端口和认证信息，再确认出口名称。链接中的 `#备注` 可作为默认名称。支持 `http://[用户名:密码@]地址:端口`、`socks5://[用户名:密码@]地址:端口` 和 `ss://`；认证字段支持百分号编码，IPv6 地址需加方括号。SS 支持 SIP002 的 Base64 用户信息、明文用户信息及旧版整段 Base64 格式，支持 AEAD 和 Shadowsocks 2022，不支持插件、查询参数或其他协议。

HTTP 出口固定阻止 UDP；SOCKS5、SS 默认阻止 UDP，仅在确认服务支持后输入 `y` 开启。程序不会自动测出 UDP 能力。“修改出口”也使用分享链接，可更换协议，保留已有出口绑定。

“3 出口管理 → 4 测试连接”：SOCKS5 检查握手及所配置的认证（也支持无认证）；HTTP、SS 仅检查 TCP 端口是否可连接，不验证协议或密码。所有检查都不证明实际转发或 UDP 可用。不支持 UDP 的代理出口会阻止 UDP 流量，不会自动改用 VPS 直连。

“3 出口管理 → 5 切换用户出口”依次按名称和编号选择用户、节点、出口，只改变这个用户在这个节点上的线路。**直连（DIRECT，不经过代理出口）是明确的编号选项**；输入对应编号才能切换到直连，不再通过留空回车选择。选择时输入 `0` 取消，不改变当前出口。

切换后，之前的出口仍保存在该用户的这个节点下。需要移除时，使用“移除已保存的出口”；如果它正在使用，先切换到另一个出口或直连，再移除。

“删除出口”会删除出口本身。只要有用户仍保存着这个出口，即使没有正在使用，也不能删除。请先在相关用户和节点下移除它。

## 检查配置、启动服务和获取分享链接

“检查配置并启动服务”会调用 sing-box 检查生成的配置，再写入配置、启动或重启服务，并检查服务和监听端口。首次成功后，用户、节点和出口等设置的修改也会自动检查并更新服务。

应用失败时，程序会尝试恢复之前的管理数据、配置和服务状态。如果恢复也失败，会保留 `transaction.json` 恢复记录并阻止继续修改。请先检查服务日志和系统环境，不要删除恢复记录来绕过保护。

通过“1 节点管理 → 1 查看节点”，在终端查看各节点下已启用授权用户的分享链接，复制对应用户的链接并导入支持该协议的客户端。没有已启用授权用户的节点不会生成分享链接。

分享链接含有连接密钥，请像密码一样保管，不要提交到代码仓库、公开上传或贴出完整分享链接。生成链接不代表节点已经连接测试通过。

## 备份、恢复和排查问题

进入“6 备份与恢复”，使用“1 创建备份”“2 查看备份”“3 从备份恢复”和“4 设置保留数量”管理备份。恢复时按编号选择备份；确认恢复会替换当前管理数据和配置，输入 `y` 才会继续。恢复前会检查配置，并另存一份当前数据的备份。

设置保留数量时至少保留 1 份，超出数量的旧备份会被删除。备份含有明文密码和连接密钥，不要公开。若有未完成的配置恢复，下次读写数据前会先尝试恢复；失败时先解决服务或环境问题，不要手动删除恢复记录。

“检查证书”只显示 DNS 解析结果和本地缓存证书的有效期，实际申请与续期由 sing-box 完成。这些结果不能证明公网证书验证已经通过。

连接失败时，结合“5 服务管理”中的“1 查看状态”“3 查看日志”和“4 检查证书”排查，并确认域名指向正确地址、HTTP-01 使用的公网 TCP 80 可以到达 VPS 源站、节点端口可达，再用客户端实际测试。不支持 DNS-01，Cloudflare 的解析、代理和回源规则需要自行设置。
