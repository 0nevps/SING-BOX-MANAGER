# 使用指南

`sbmanager` 和 `python3 main.py` 都要求 Linux + root，统一使用 `/var/lib/sbmanager/` 保存管理数据、`/etc/sbmanager/config.json` 保存服务配置，并管理真实系统服务。普通用户请用 `sudo sbmanager` 启动，已在 root 终端中时可直接运行 `sbmanager`。

保存设置成功不等于节点可以连接。请检查服务状态、证书和网络，并使用客户端实际测试。

## 先认识节点、用户和出口

- **节点（手机或电脑连接的入口）**：本工具提供 REALITY、Hysteria2 和 WebSocket 三种节点。
- **用户**：可以单独设置节点使用权限、启用或停用的连接身份。
- **出口（VPS 访问网络时使用的线路）**：同一个用户在不同节点上，可以使用不同出口。
- **直连（DIRECT，不经过代理出口）**：让 VPS 直接访问网络。
- **连接密钥（UUID 或密码）**：客户端连接节点时使用的信息，不要公开。

输入菜单编号即可操作。先选择分类，再选择具体功能；选择用户、节点或出口时，按名称找到对象并输入列表编号，不需要复制 ID。各子菜单输入 `0` 返回主菜单，选择对象时输入 `0` 取消当前选择。

菜单采用单列编号、分组标题和统一分隔线，保持原有操作编号。危险操作标记 `[危险]`，需留意的操作标记 `[注意]`，不只依赖颜色区分。菜单标签会按终端宽度折行；不清屏，方便回看操作结果。交互终端使用颜色，重定向输出、`TERM=dumb` 或设置 `NO_COLOR` 时使用纯文本，例如 `NO_COLOR=1 sbmanager`。

## 菜单能做什么

下文用“主菜单 → 子菜单”表示操作路径。例如“2 用户管理 → 4 开通节点”，就是先输入 `2`，再输入 `4`。

| 2 | 用户管理 |
| 3 | 出口管理 |
| 4 | 服务管理 |
| 5 | 备份与恢复 |

### 1 节点管理

| 编号 | 菜单名称 | 用途 |
| --- | --- | --- |
| 1 | 查看节点 | 查看节点参数及已启用授权用户的分享链接（含连接密钥，请勿公开）；无可用用户时不生成链接。 |
| 2 | 添加节点 | 选择协议，使用默认名称或填写名称，一次完成地址、端口和协议参数，校验后保存。 |
| 3 | 修改节点 | 名称和协议不可修改；其余连接参数与添加一致，回车保留当前值，不重置用户密钥。 |

| 5 | 首次设置向导 | 没有用户和节点时，选择要安装的节点及创建第一个用户，不默认安装全部，不覆盖已有数据。 |

| 7 | 重置连接密钥 | 更换指定用户在指定节点上的 UUID 或密码。 |
| 8 | 删除用户 | 删除用户及其全部节点权限、出口选择。 |

更新管理程序时，安装器会在终端要求输入 `yes` 确认；服务正在运行时可能短暂中断，失败时尝试回滚。卸载前会列出具体路径，只有输入 `yes` 才执行，其他输入取消。卸载无法撤销，成功后退出程序；手动导出到其他目录的文件、共享系统日志和系统依赖不会删除。

## 按名称和编号选择对象

默认显示友好列表，不再要求从 JSON 中复制用户、节点或出口 ID。可以先在相应分类的“查看节点”“查看用户”“查看出口”中了解当前设置，再进入操作并按名称选择编号。编号以当前显示的列表为准；选择对象时输入 `0` 取消。

切换出口时，直连（DIRECT，不经过代理出口）是列表中的明确编号选项。需要直连时输入它对应的编号；不要留空回车，也不要输入或复制出口 ID。`0` 表示取消，不表示直连。

## 高级：查看原始设置 JSON

只有“6 高级与帮助 → 1 查看原始设置JSON”显示原始设置 JSON，日常操作不需要使用。**用户 ID、节点 ID、出口 ID 不是名称，也不是客户端连接使用的 UUID 或密码。** 排查时可参考以下字段，不需要手写或修改 JSON：

| 字段 | 含义 |
| --- | --- |
| `users` | 用户列表；每个用户的 `id` 是用户 ID，`name` 是用户名。 |
| `inbounds` | 节点列表；每个节点的 `id` 是节点 ID，旧提示中的“入站 ID”也是它。 |
| `egress` | 出口列表；每个出口的 `id` 是出口 ID。 |
| `protocol` | 协议名称：`reality`、`hysteria2`、`cloudflare_ws` 或出口的 `socks5`。 |
| `enabled` | 用户是否启用：`true` 是启用，`false` 是停用。 |
| `grants` | 该用户获准使用的节点 ID 列表，不显示连接密钥。 |
| `bindings` | 用户在各节点上的出口设置，包含 `user_id`、`inbound_id`、`saved` 和 `active`。 |
| `saved` | 这个用户在这个节点上保存过的出口 ID。 |
| `active` | 当前使用的出口 ID；`null` 表示直连（DIRECT，不经过代理出口）。没有对应的出口设置时也默认直连。 |
| `settings` | 节点的地址、端口等参数，或出口的服务器和账号等参数。 |

列表会隐藏部分敏感字段，但不要因此把整份数据当作可以公开的内容。客户端连接密钥需要通过“导出客户端配置”获取，不是从 `id` 字段复制。

## 第一次设置与手工添加

每次运行 `sbmanager` 都先显示主菜单，首次使用也不会自动进入设置。安装器完成后，有交互终端时也会打开主菜单。需要首次设置时，主动选择“1 节点管理 → 5 首次设置向导”。

向导先让你选择要安装的节点：`1 VLESS + REALITY + Vision`、`2 Hysteria2`、`3 VLESS + WebSocket + TLS`。可用空格或逗号分隔多选，例如 `1 3`；输入 `0` 取消，留空不会默认安装全部。只询问所选节点需要的参数，并创建第一个用户、开通所选节点。第一个用户名直接回车默认为 `default`，也可以自己填写。已有用户或节点时，向导不会覆盖数据。

手工添加时，按下面顺序操作：

1. 用“1 节点管理 → 2 添加节点”一次填写协议、名称和连接参数。名称默认使用协议全名，重名时自动追加编号；输入 `0` 取消，不保存半成品节点。后续通过“3 修改节点”调整参数，名称不可修改。
2. 用“2 用户管理 → 2 添加用户”创建用户。
3. 用“2 用户管理 → 4 开通节点”，按名称和编号选择用户、节点并开通权限。也可以用“2 用户管理 → 3 添加用户并开通全部节点”一次创建新用户并开通全部已有节点。
4. 如果要使用代理出口，先用“3 出口管理 → 2 添加SOCKS5”，再用“3 出口管理 → 3 切换用户出口”。不设置代理出口时默认直连。
5. 首次使用需要主动选择“4 服务管理 → 2 检查配置并启动服务”，之后才能继续检查客户端连接。

每个用户在每个节点上的权限和连接密钥是分开的。停用用户会保留节点权限和出口设置；取消某个节点权限只清除该节点下的权限和出口设置；删除用户会清除该用户的全部权限和出口设置。

重置连接密钥后，该用户在对应节点上的旧客户端配置会失效，需要重新导出并更新客户端。

## 节点地址、端口和 WebSocket 路径

每种协议只询问一次“在 VPS 上使用的端口”：

- REALITY 默认 TCP 443，手机或电脑直接连接这个端口。
- Hysteria2 默认 UDP 443，手机或电脑直接连接这个端口。
- WebSocket 先选择直接连接 VPS，还是经过 Cloudflare 代理，再填写 VPS 端口，默认 TCP 8443。直接连接 VPS 时，客户端使用相同端口；经过 Cloudflare 时，客户端连接 HTTPS 443，需要你自行在 Cloudflare 设置回源到 VPS 所填端口的规则。

这里的“直接连接 VPS”是手机到 VPS 的连接方式，与 VPS 访问网络时使用的直连出口是两回事。程序只生成节点配置，不会自动设置 Cloudflare。

修改旧配置时，如果已有不同的客户端端口和 VPS 端口，程序会提示保留原设置还是重新设置，避免覆盖已有端口转发安排。

WebSocket 路径首次留空会随机生成并显示；修改已有节点时留空会保留原路径。路径需要以 `/` 开头，不能包含空格、`?` 或 `#`。更改路径或端口后，请重新导出客户端配置，并同步更新 Cloudflare 等转发服务的规则。

## REALITY 的握手目标和 SNI

握手目标是 REALITY 使用的目标服务器；SNI 是握手时发送的域名，需要与目标证书匹配。

首次设置或修改 REALITY 节点时，先填写握手目标域名，再填写 SNI。SNI 留空会使用同一个域名；也可以自己填写与目标证书匹配的其他域名。程序没有固定的备选域名列表。

保存前，程序会连接目标的握手端口，默认 TCP 443，检查：

- 能否连接并完成 TLS 1.3 握手。
- 证书是否由系统信任的 CA 签发、是否在有效期内，以及是否与 SNI 匹配。

连接、握手或证书检查失败时，不保存修改。检查从运行管理器的机器发出，在本地电脑检查通过不代表 VPS 也能连接目标。基础检查也不能证明目标满足所有 REALITY 条件，仍需用 REALITY 客户端实际测试。

WebSocket TLS 应填写你自己的节点证书域名，不使用 REALITY 的默认规则。

## 添加和切换出口

“3 出口管理 → 2 添加SOCKS5”需要填写服务器地址、端口、用户名和密码。是否支持 UDP 需要你根据出口服务的实际情况明确填写；程序不会自动测出 UDP 能力。

“3 出口管理 → 4 测试连接”只检查 SOCKS5 握手和账号密码是否通过，不证明出口能转发到目标网站，也不证明 UDP 可用。不支持 UDP 的代理出口会阻止 UDP 流量，不会自动改用 VPS 直连。

“3 出口管理 → 3 切换用户出口”依次按名称和编号选择用户、节点、出口，只改变这个用户在这个节点上的线路。**直连（DIRECT，不经过代理出口）是明确的编号选项**；输入对应编号才能切换到直连，不再通过留空回车选择。选择时输入 `0` 取消，不改变当前出口。

切换后，之前的出口仍保存在该用户的这个节点下。需要移除时，使用“移除已保存的出口”；如果它正在使用，先切换到另一个出口或直连，再移除。

“删除出口”会删除出口本身。只要有用户仍保存着这个出口，即使没有正在使用，也不能删除。请先在相关用户和节点下移除它。

## 检查配置、启动服务和导出

“检查配置并启动服务”会调用 sing-box 检查生成的配置，再写入配置、启动或重启服务，并检查服务和监听端口。首次成功后，用户、节点和出口等设置的修改也会自动检查并更新服务。

应用失败时，程序会尝试恢复之前的管理数据、配置和服务状态。如果恢复也失败，会保留 `transaction.json` 恢复记录并阻止继续修改。请先检查服务日志和系统环境，不要删除恢复记录来绕过保护。

通过“2 用户管理 → 9 导出客户端配置”，按名称和编号选择已启用用户，再填写一个**尚不存在的新目录**，会生成：

- `client.json`：客户端配置，包含本机 `127.0.0.1:2080` 的混合代理入口和可切换的节点列表。
- `links.txt`：该用户有权使用的节点分享链接。

导出目录使用 `0700` 权限，文件使用 `0600` 权限。导出内容含有连接密钥，请像密码一样保管，不要提交到代码仓库、公开上传或贴出完整分享链接。导出成功不代表节点已经连接测试通过。

## 备份、恢复和排查问题

进入“5 备份与恢复”，使用“1 创建备份”“2 查看备份”“3 从备份恢复”和“4 设置保留数量”管理备份。恢复时按编号选择备份；确认恢复会替换当前管理数据和配置，输入 `yes` 才会继续。恢复前会检查配置，并另存一份当前数据的备份。

设置保留数量时至少保留 1 份，超出数量的旧备份会被删除。备份含有明文密码和连接密钥，不要公开。若有未完成的配置恢复，下次读写数据前会先尝试恢复；失败时先解决服务或环境问题，不要手动删除恢复记录。

“检查证书”只显示 DNS 解析结果和本地缓存证书的有效期，实际申请与续期由 sing-box 完成。这些结果不能证明公网证书验证已经通过。

连接失败时，结合“4 服务管理”中的“1 查看状态”“3 查看日志”和“4 检查证书”排查，并确认域名指向正确地址、HTTP-01 使用的公网 TCP 80 可以到达 VPS 源站、节点端口可达，再用客户端实际测试。不支持 DNS-01，Cloudflare 的解析、代理和回源规则需要自行设置。
