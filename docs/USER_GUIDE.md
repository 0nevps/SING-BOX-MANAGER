# 使用指南

## 用户和入站

首次向导创建三种入站和首个用户。也可以手工添加入站档案，再配置端口、域名和 REALITY 参数。列表显示 ID；后续操作按 ID 选择，避免重名造成歧义。

用户授权按入站隔离。禁用保留授权和绑定；撤销某个入站授权只清理该入站绑定；删除用户清理全部授权与绑定。重置凭据后旧客户端配置失效，需重新导出。

## REALITY 的 SNI 与握手目标

初始化及入站配置时，先填写 REALITY 握手目标域名，再填写 SNI；SNI 留空默认使用同一域名，也可手动指定与目标证书匹配的其他域名。没有固定备选列表。

保存前连接目标握手端口（默认 TCP 443），要求 TLS 1.3，并使用系统 CA 验证证书信任链、有效期和 SNI 匹配。连接、握手或证书校验失败时不保存修改。检测从运行管理器的机器发出，本地测试通过不代表 VPS 网络也可连接。

基础检测通过仍需 REALITY 客户端实际验证；检测不会证明所有 REALITY 兼容条件。WebSocket TLS 仍填写自己的节点证书域名，不使用 REALITY 的默认规则。

## 出口

添加 SOCKS5 档案时输入服务器、端口及认证资料。UDP 由用户明确声明；出口测试只验证 SOCKS5 握手和认证。TCP-only 出口的 UDP 在路由中被拒绝。

切换出口会保留之前保存的出口；留空出口 ID 明确选择 DIRECT。解除当前出口绑定前先切换至其他出口或 DIRECT。被引用出口禁止删除。

## 部署和导出

“校验并部署”检查官方配置后写入、重启并检查服务。首次部署成功后，业务修改自动走相同事务。失败时恢复业务状态及配置；恢复失败保留 transaction.json 并停止后续修改。

导出指定已启用用户至新的私有目录，生成 `client.json` 和 `links.txt`。客户端 JSON 使用本地 2080 混合代理和节点选择器；导出文件必须按敏感凭据保管。

## 备份与故障

手动备份、查看、恢复和清理均通过菜单完成。恢复前会校验并另存当前备份。若有待恢复事务，下次读写会先尝试恢复；服务无法恢复时先检查日志和环境，不要删除恢复日志以绕过保护。

证书菜单展示 DNS 和本地缓存证书有效期；实际签发和续期由 sing-box 完成。服务日志、域名解析、TCP 80 公网可达性和客户端连接需要综合排查。
